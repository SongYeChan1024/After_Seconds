## 2026-10-28 플레이어 구현 이후 최신 상태

작성자 송예찬. 아래 내용이 현재 기준이며, 뒤의 에셋 반입·초기 AD·초기 학습 순서 기록보다 우선한다. 과거 기록은 당시 결정과 작업 경위를 확인하기 위해 보관한다.

**집에서 시작:** 최신 `main`을 먼저 받는다. 이번 변경은 플레이어 코드·SampleScene·설정 에셋·Pipeline/Cinemachine 패키지 설정과 문서를 함께 관리한다. VARCO 브릿지는 기본 의존성에서 분리했으므로 학원 PC의 Downloads 경로 없이 열 수 있으며, 기존 FBX 에셋도 그대로 사용한다.

- 사용자가 의사코드·코드·주석을 직접 작성하고 Inspector를 연결했으며, 플레이어 이동과 마우스 시야 회전이 동작하는 것을 확인했다. 다음 단계도 사용자가 분석·의사코드·구현하고 Codex가 검토하는 흐름을 유지한다.
- `PlayerInput`의 `Invoke Unity Events`에서 Move → `PlayerPresenter.OnMove`, Look → `PlayerPresenter.OnLook`를 연결했다. Presenter는 입력값을 보관하고, 매 프레임 **`PlayerLook.Rotate(lookInput)` → `PlayerMotor.Move(moveInput, Time.deltaTime)`** 순서로 호출한다. 회전한 플레이어 방향을 기준으로 이동하며, 입력이 0이어도 Motor의 중력 처리는 계속한다.
- `PlayerMotor`는 `CharacterController`로 이동·접지를 처리한다. 이동·시야 수치는 `06.Data`의 ScriptableObject로 분리했다. 현재 `PlayerMotorSettings.asset`은 이동 속도 💡 4.6, 중력 크기 💡 20, 접지 유지 수직 속도 💡 -2인 테스트 설정이다.
- `PlayerLook`은 플레이어의 좌우 회전과 `CameraRoot`의 상하 회전을 나눈다. 씬에는 `06.Data/PlayerLookSettings.asset`이 연결되어 있으며, 현재 좌우·상하 감도는 각각 💡 0.1, 상하 각도 범위는 💡 -80°~80°다. Cinemachine **2.10.7**의 Virtual Camera가 `CameraRoot`를 따라가고 실제 Main Camera의 Brain이 화면에 반영한다.
- `SystemAD`에는 `Unity.InputSystem`, `PresenterAD`에는 `SystemAD`와 `Unity.InputSystem` 참조를 연결했다. 기존 `PlayerInputSystem.cs`는 보관만 하고 현재 입력 흐름에는 사용하지 않는다.
- CP949로 저장했던 한글 주석의 인코딩 문제를 복구했다. 현재 C# 소스는 UTF-8 기준이며, Unity 프로젝트 루트의 `.editorconfig`에 `charset = utf-8-bom`을 지정해 집과 학원의 편집 설정을 맞췄다.
- Unity CLI **1.0.0-beta.13**와 Pipeline **0.9.1-exp.1**로 직접 조회한다. Unity AI Assistant는 제거했으며 CLI에 AI 구독이나 MCP 설정은 필요하지 않다. 설치·로그인·프로젝트 경로·읽기 전용 명령과 VARCO 브릿지 선택 설치는 [루트 README의 집 CLI 안내](../README.md#집에서-unity-cli로-이어하기)를 따른다. 브릿지를 선택 설치해 생기는 PC별 절대 `file:` 경로는 다시 커밋하지 않는다.
- 외형 후보는 `05.Model/{Player,Enemy,Props}`에 분류했다. `04.Prefabs`는 스크립트를 결합해 기능이 완성된 에셋용으로 남겨 둔다. 캐릭터 후보는 계속 정적 T포즈이며 리깅과 애니메이션은 아직 연결하지 않았다.
- 플레이어 모델 프리팹에는 Motor·Presenter 등이 일부 연결되어 있지만 CameraRoot·PlayerLook은 SampleScene에 추가한 구성이다. 현재 SampleScene에서 동작을 확인한 상태이며, 프리팹 하나만으로 독립 실행되는 완성 플레이어는 아직 아니다. 궤짝의 현재 파일명은 `05.Model/Props/Props_Crate_V0.1.prefab`이다.

**2026-10-29 이어갈 계획:** 애니메이션 연결, 점프, 달리기, 상호작용을 차례로 분석하고 구현한다. 기존 VARCO 더미에는 뼈대·스킨이 없으므로 애니메이션에 사용할 모델의 리깅 상태부터 확인한다. 교환 예약·미리보기 등 퍼즐 규칙 구현은 아직 남아 있다.

Text → Generate Image → Generate 3D가 6개 있으며 각 이미지·3D 결과가 표시되는 것을 확인했다. 설정은 Private·Triangle·목표 8,000 triangles·1K texture·count 1, 인간 더미는 T-Pose 옵션이다. 최초 6개 파이프라인 실행 예상 비용은 1,500크레딧(이미지 50+3D 200을 6회)이다. 실제 결제 내역이나 출력 메쉬 수치는 별도로 측정하지 않았다.

**아직 하지 않은 것:** 3D 파일 로컬 반입, Unity 프리팹화, 실제 치수·pivot·UV·충돌체·LOD·Humanoid 리깅·애니메이션·플레이 검수. 이미지 다운로드 기능은 세션에서 완료되지 않았고, 결과는 바르코 플로우에 보존되어 있다. 로컬에는 결과 전체 화면을 기록했다. 생성 완료를 '즉시 사용할 수 있는 최종 게임 에셋'으로 오해하지 않는다.

공통 스타일 원문과 더미용 템플릿은 기획서 10.2 및 바르코 Note에 있다. 미술 시안의 48×32m 외곽·약 6m 층고는 가안이다. 원래 방별 배치 표와 SVG를 치환하거나 일괄 확대하지 않는다. 직원 통로·냉각조 가장자리로 퍼즐을 건너뛰지 못하게 그레이박스로 검증해야 한다.

## 초기 루시드 다이버 분석과 작업 제안 (2026-10-26 보관)

참고 저장소:

- https://github.com/Jin-o12/Document_LucidDiver
- https://github.com/Jin-o12/UnityProject_LucidDiver

원본: Define → Utils → System·UI → Manager·Presenter. 실제 asmdef에서는 UI→System, Presenter→Manager 참조도 있다. 순환 참조 방지와 책임 분리를 참고한다. 원본 Define은 Unity에 의존한다.

After Seconds 제안: Define을 순수 값·계약으로, Simulation을 순수 시간·예약·교환·경비 Step으로 분리한다. Unity의 입력·물리·SO는 System 어댑터에 둔다. UI는 표시, Manager는 수명·조립, Presenter는 연결을 맡는다. 전체 자세한 참조표·예제 흐름은 학습 안내 문서에 있다.

다음 세션 과제:

1. 저장한 Define·Simulator 설정과 Unity Console 상태를 확인한다. 폴더·asmdef 생성은 완료했다.
2. `EntityId`, `EntityState`, `RuleSettings`, `ScheduledAction`에 무엇이 들어가는지 적는다.
3. `ScheduleSwap`, `AdvanceTo`, `ExecuteSwap` 의사코드를 쓴다.
4. 같은 시각 예약 순서, 2.9→3.2초 tick, 움직이는 대상, 무효·손에 든 대상 취소, 재시작 시 큐 초기화를 설명한다.
5. 그 다음 작은 구현으로 확인한다. 3초 예약→교환이 안정된 뒤 더미 이동·총·경비·발판·문·미리보기 순으로 진행한다.

미정 유지: A안(손 힘 3초 뒤)과 B안(손 힘 즉시)의 최종 선택, 여러 예약/눈 없는 대상의 시야 창, 전체 방 플레이 검증. 사용자에게서 추가 에셋 요청이 오면 그 범위부터 이어간다.

## 새 채팅에 붙여 넣을 문장

> 최신 main을 받은 뒤 이 문서 맨 위의 2026-10-28 상태와 루트 README, Unity 프로젝트 README를 읽고 이어가 줘. Unity 6000.4.0f1의 SampleScene에서 PlayerInput → Presenter → Look·Motor를 연결해 이동과 마우스 시야 회전을 확인했어.
