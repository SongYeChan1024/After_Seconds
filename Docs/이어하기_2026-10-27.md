# After Seconds 집에서 이어하기 V0.01

2026-10-27 · 작성자 송예찬

오늘은 `Kasil/pseudocode-Create` 브랜치를 만들고, 사용자가 직접 작성할 [교환예약하기 분석과 의사코드](교환예약하기_분석과_의사코드.md) 틀을 준비했다. 분석 답안과 의사코드는 아직 `[작성]`으로 남아 있다.

## 오늘 결정한 진행 방식

- 집 PC에 만들어 둔 AD와 폴더 구조를 기준으로 이어간다. 해당 작업이 원격에 올라오기 전에는 여기서 AD나 구조를 다시 만들지 않는다.
- 사용자가 직접 기능을 분석하고 의사코드를 쓴다. Codex는 문서 틀을 준비하고, 작성한 내용의 조건·순서·이유를 검토한다.
- 첫 과제는 `교환예약하기`다. 명중 결과를 받아 예약을 남기는 범위부터 분석하며, 이후 `예약처리하기`, `교환실행하기`로 이어간다.
- C# 스크립트 안에 주석으로 의사코드를 적어도 된다. 지금은 문서에서 분석한 뒤 집의 구조를 확인하고 스크립트 위치를 정한다.
- 사용자가 이번 전달 범위를 의사코드·이어하기 문서로 정했다. 학원 PC의 `Unity_Project_After_Seconds/Unity.6.4_URP_Tanks`는 커밋에서 제외하고 그대로 둔다.

## 브랜치와 프로젝트 상태

GitHub에서 만든 브랜치 이름은 **`Kasil/pseudocode-Create`**다. 학원 PC에서도 이 브랜치를 받아 전환했다. 분기한 기준 커밋은 `013564f`이며, 오늘 원격 확인 당시 `main`에는 집에서 만든 AD·구조 변경이 없었다.

이 브랜치에서 추가한 전달 문서는 다음 두 개다.

- [교환예약하기 분석과 의사코드 V0.01](교환예약하기_분석과_의사코드.md)
- 이 이어하기 기록

Unity 코드, AD, 폴더 구조, 메인 기획서와 Google Docs는 이번 작업에서 수정하지 않았다. 이전 에셋·기획·Unity 준비 내역은 [10월 26일 이어하기](이어하기_2026-10-26.md)에 있다.

## 집에서 이어갈 순서

1. 집 저장소에서 아래 명령으로 현재 브랜치와 커밋되지 않은 변경을 확인한다. 편집기에만 남아 있는 내용도 먼저 파일로 저장한다.

   ```powershell
   git status --short --branch
   git remote -v
   ```

2. 집의 AD·구조 변경이 아직 커밋되지 않았다면 **현재 작업 브랜치에서 해당 변경을 먼저 커밋·푸시**한다. `.asmdef`와 관련 `.meta`, 구조 설계 문서를 함께 확인한다. 변경을 삭제하거나 강제로 브랜치를 전환하지 않는다.

3. 집 작업을 보존한 뒤 의사코드 브랜치를 받는다. 원격 저장소는 `https://github.com/SongYeChan1024/After_Seconds.git`이다.

   ```powershell
   git fetch origin
   git switch Kasil/pseudocode-Create
   git pull --ff-only
   git status --short --branch
   ```

   같은 이름의 로컬 브랜치가 없고 해당 원격 브랜치만 있다면 `git switch`가 추적 브랜치를 만든다. 명령이 오류를 내면 강제 옵션을 붙이지 말고 출력 내용을 확인한다.

4. 의사코드 문서의 **1장 기능과 규칙 분석**부터 `[작성]`을 채운다. 먼저 함수 역할을 한 문장으로 설명하고, 입력·보관할 데이터·처리 순서의 이유를 적는다.

5. 집의 AD 작업을 올린 브랜치와 커밋을 확인해 Codex에게 검토를 요청한다. AD가 다른 브랜치에 있으면 이 의사코드 브랜치로 전환하는 것만으로 합쳐지지는 않는다. 실제 구조를 확인한 뒤 병합 방향을 정한다.

## 분석할 때 참고할 기준

[메인 기획서](AfterSeconds_메인기획서.md)의 4.1 예약 큐, 4.2 교환, 6.1 지연을 읽는다. [계층 설계와 학습 순서](Unity_계층_설계와_학습_순서.md)는 설계 제안이며, 집에서 사용자가 만든 구조를 확인하고 비교해야 한다.

교환 지연은 각 명중 시각부터 계산한다. 실행 시각이 같으면 등록 순서로 처리하고, 실제 위치는 교환을 처리할 때 읽는다. 처음에는 명중 결과가 이미 전달된 것으로 가정하고 예약 등록만 분석한다.

후속 검토 사항: 기획서 2.1의 붙잡힘 유예 중 교환으로 탈출하는 설명과 4.1의 붙잡히면 교환 예약을 취소하는 규칙은 함께 정리해야 한다. 첫 과제는 붙잡힘이 없는 상황으로 한정한다.
