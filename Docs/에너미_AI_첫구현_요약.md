# After Seconds 에너미 AI 첫 구현 요약 V0.03

작성자 송예찬 · 2026-11-10

[에너미 AI 기획과 로직](에너미_AI_기획과_로직.md)의 1~2단계, **경비 1명이 순찰하고, 보면 쫓고, 놓치면 찾다가 돌아가는 것**만 모은 요약이다. 의사코드를 쓰기 전에 이 문서 하나로 범위를 잡을 수 있게 했다. 수치는 모두 💡 시험값이고 확정이 아니다. 게임 코드는 아직 없다.

**플레이어 핵심 기능을 먼저 완성한다.** 이 문서는 그 뒤 에너미 AI에 착수했을 때 쓰는 것이며, 플레이어에서 마련한 공통 게임 시계와 교환 시스템을 재사용한다.

## 1. 이 단계에서 만드는 것과 만들지 않는 것

| 만든다 | 만들지 않는다 |
| --- | --- |
| 경비 1명 | 경비 여러 명, 무전, 구역 배정 |
| 순찰 · 추격 · 수색 · 복귀 네 상태 | 의심 · 조사 · 무력화 상태 |
| 직접 시야로 보는 것 | 소리, 소음 풀 |
| 마지막으로 본 위치 하나 | 전달받은 보고, 사건 ID, 채널 |
| 붙잡기 | 피격 반응, 교환, 제압, 사격 |
| 0.1초마다 한 번 판단 | 시설 경보, CCTV, 연구원, 층 전환, 미리보기 |

피격과 교환은 3단계, 소리는 4단계, 두 번째 경비는 5단계에서 붙인다.

## 2. 어디에 무엇을 두는가

| 계층 | 이 단계에서 넣을 것 |
| --- | --- |
| A.Define | 관측 한 건(위치 · 시각 · 종류), 경비 상태 이름, 행동 의도. Unity 타입 없이 숫자로 표현 |
| B.Simulator | 한 틱의 판단. 기억 갱신, 상태 전환, 붙잡기 조건. Unity를 부르지 않는다 |
| C.System | 실제 시야 검사와 이동. 판단에 넘길 입력을 만들고, 돌려받은 의도대로 움직인다 |
| E.Manager | 플레이어 쪽에서 만든 공통 게임 시계를 쓴다. `FixedUpdate` 5회마다 한 번 판단을 부른다 |
| F.Presenter | 감지 결과를 판단에 연결하고, 의도를 이동과 애니메이션에 전달 |

A.Define과 B.Simulator는 지금도 Unity 엔진을 참조하지 않게 설정돼 있다. 판단을 여기에 두면 Unity를 켜지 않고도 "이 입력이면 이 결과"를 확인할 수 있다.

## 3. 한 틱에 오가는 것

**판단에 들어가는 입력** — C.System이 틱마다 만든다.

| 입력 | 뜻 |
| --- | --- |
| 지금 시각, 틱 간격 | 게임 시각과 0.1초 |
| 플레이어가 보이는가 | 거리 · 시야각 · 가림을 모두 통과했는지 |
| 보이는 위치 | 보일 때만 값이 있다. 안 보이면 넘기지 않는다 |
| 플레이어와의 몸 사이 거리 | 붙잡기 판단용. 손이 닿는 경로가 있는지도 함께 |
| 가려던 곳에 도착했는가 | 순찰 지점, 마지막 본 위치, 복귀 지점 공통 |

**경비가 기억하는 것** — 틱이 끝나도 남는다.

| 기억 | 뜻 |
| --- | --- |
| 현재 상태 | 순찰 · 추격 · 수색 · 복귀 중 하나 |
| 식별 진행도 | 보이는 동안 차오르고, 안 보이면 줄어드는 값 |
| 마지막 관측 | 위치 · 시각 · 종류 한 건 |
| 순찰 지점 번호 | 다음에 갈 순찰 지점 |
| 수색에 남은 시간 | 수색을 언제 끝낼지 |
| 붙잡기 예고에 남은 시간 | 예고 중일 때만 |

**판단에서 나오는 출력** — C.System과 F.Presenter가 받아 실행한다.

| 출력 | 뜻 |
| --- | --- |
| 갈 곳 | 좌표 하나 |
| 이동 속도 종류 | 순찰 속도인지 추격 속도인지 |
| 바라볼 방향 | 수색 중 둘러볼 때 |
| 붙잡기 신호 | 예고 시작 · 취소 · 성립 |

입력에 "안 보이는 플레이어의 현재 위치"가 없다는 점이 이 설계의 핵심이다. 판단은 받은 것만 안다.

## 4. 네 상태의 전환

| 지금 상태 | 일어난 일 | 다음 상태 |
| --- | --- | --- |
| 순찰 | 식별 진행도가 기준에 닿음 | 추격 |
| 추격 | 계속 보임 | 추격 유지. 마지막 관측을 지금 위치로 갱신 |
| 추격 | 안 보이게 됨 | 추격 유지. 마지막 관측 위치로 계속 감 |
| 추격 | 안 보이는 채로 마지막 관측 위치에 도착 | 수색 |
| 수색 | 다시 식별됨 | 추격 |
| 수색 | 수색 시간이 끝남 | 복귀 |
| 복귀 | 다시 식별됨 | 추격 |
| 복귀 | 복귀 지점에 도착 | 순찰 |

붙잡기는 상태가 아니라 추격 중에 겹쳐 일어나는 일이다. 범위에 들어오면 예고를 시작하고, 예고가 끝나는 순간 조건을 다시 본다.

## 5. 시험값

출처는 [잠입·상호작용 상세 설계 4장](잠입_상호작용_상세설계.md#4-경비-수치와-공간-시험)이다.

| 항목 | 시험값 | 비고 |
| --- | --- | --- |
| 판단 간격 | 0.1초 | `FixedUpdate` 0.02초의 5회. 판단은 그 호출 시점의 위치를 읽는다. 이번 스텝의 물리 결과는 아직 반영되기 전이다 |
| 순찰 속도 | 1.5m/s | |
| 추격 속도 | 6.0m/s | 플레이어 걷기 5보다 빠르고 달리기 7.5보다 느림 |
| 시야 거리 · 각도 | 15m · 좌우 합쳐 90° | |
| 붙잡기 거리 · 예고 | 몸 사이 0.9m · 0.4초 | 예고 동안 경비는 계속 따라붙는다(사용자 결정) |
| 경비가 몸을 돌리는 속도 | 정해지지 않음 | 직접 정해 시험한다. 느릴수록 옆을 스쳐 지나가기 쉽다 |
| 식별 기준 · 차오르는 속도 | 정해지지 않음 | 직접 정해 시험한다 |
| 수색 시간 | 정해지지 않음 | 직접 정해 시험한다 |

## 6. 먼저 정해야 하는 것

1. **붙잡기의 남은 값.** 예고 동안 경비가 이동과 회전을 계속해 따라붙는 것은 정해졌다([AI 문서 6.4](에너미_AI_기획과_로직.md#64-붙잡기의-성립과-실패)). 남은 것은 경비가 몸을 돌리는 속도와, 교환이 같은 순간에 겹칠 때 무엇을 먼저 처리할지다. 순찰 · 추격 · 수색 · 복귀를 먼저 만들고 붙잡기를 그 위에 얹어도 된다.
2. **시험할 곳.** 네 층 씬에는 길찾기 데이터가 없다. 이 단계는 순찰 지점 두 곳과 마지막 관측 위치로 곧게 가는 이동만으로 충분하므로 장애물 없는 직선 구간에서 시작한다. B5의 T02 통로(직선 13.8m)가 맞는다.

## 7. 의사코드를 쓰기 전에 스스로 답해 볼 질문

답을 적어 본 뒤 [AI 문서 13.1](에너미_AI_기획과_로직.md#131-고정-틱과-최소-개인-판단)과 비교한다.

1. 플레이어가 보이다가 안 보이게 된 틱에, 마지막 관측의 위치와 시각은 언제의 값이어야 하는가?
2. 식별 진행도는 어떤 때 오르고 어떤 때 내려가는가? 추격에 들어간 뒤에도 이 값이 필요한가?
3. 추격 중 마지막 관측 위치로 가는 도중에 플레이어가 다시 보이면 무엇이 바뀌는가?
4. "수색이 끝났다"는 것을 판단은 무엇을 보고 아는가?
5. 게임 시간이 멈춘 동안 들어온 틱에서는 기억 가운데 무엇이 변하면 안 되는가?
6. 붙잡기 예고 중에 플레이어가 범위를 벗어나거나 벽 뒤로 가면 예고에 남은 시간은 어떻게 되는가?
7. B.Simulator는 Unity 타입을 쓸 수 없다. 위치와 방향을 무엇으로 주고받을 것인가?
8. 같은 입력을 같은 순서로 두 번 넣으면 결과가 같아야 한다. 판단 안에서 이를 깨뜨릴 수 있는 것은 무엇인가?

## 8. 다 됐는지 확인하는 방법

| 확인 | 기대하는 결과 |
| --- | --- |
| AI01 | 같은 상태와 같은 입력을 넣으면 매번 같은 상태 전환이 나온다 |
| AI08 | 모퉁이 뒤로 숨으면 마지막으로 본 곳까지 와서 둘러본다. 벽 너머의 나를 따라오지 않는다 |
| AI29 | 같은 틱별 입력을 기록해 두고 화면이 초당 30 · 60 · 144장인 환경에서 다시 넣으면 판단 결과와 순서가 같다. 플레이어 이동이 프레임마다 실행되므로, 입력을 고정하지 않은 실제 플레이의 결과가 같다는 뜻은 아니다 |
| AI25 · AI26 | 붙잡기 예고가 보이고, 끝날 때 조건을 다시 본다. 범위를 벗어나면 취소된다 |
| AI36 | 통로를 막은 경비 옆을 달려 지나갈 때, 따라붙는 경비에게 어느 경우가 잡히는지 기록한다. 플레이어가 끌려가지 않는다 |
