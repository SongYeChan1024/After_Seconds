# After Seconds 잠입·상호작용 상세 설계 V0.07

작성자 송예찬 · 2026-11-10

[메인 기획서](AfterSeconds_메인기획서.md) V0.76을 따른다. 1~6장의 추천안·키·시험값은 승인 전 제안이며, 7장에는 이후 사용자 확정사항을 별도로 정리했다. 8장은 붙잡기·미리보기·신고 대응의 추가 우선 검토안이다. 기획 확정과 기능 구현 완료를 구분한다.

[에너미 AI 기획과 로직](에너미_AI_기획과_로직.md)은 감지·기억·협력·상태 전환과 의사코드를 다룬다. 이 문서의 사격·제압·시험 수치는 해당 AI 문서에서도 미확정 제안으로 참조한다.

## 1. 우선 결정 1 — 경비 사격

모든 경비가 총을 지니고 제압 후 얻을 수 있다는 결정과, 경비가 실제로 발사한다는 결정은 다르다. 사격 여부를 먼저 정해야 원거리 위험·엄폐 간격·실패 조건을 정할 수 있다.

| 선택지 | 추가할 규칙 | 레벨에 미치는 영향 |
| --- | --- | --- |
| 💡 추천: 기본 사격 없음, 추격·생포 | 피험체 회수 지침으로 배경을 설명하는 안. 총은 소지·획득 대상 유지 | 추격 경로와 3초 동안 거리·엄폐를 만드는 판단에 집중. 총을 들었는데 쏘지 않는 이유를 장면·기록으로 전달해야 함 |
| 제압탄 사격 | 경고/조준 시간·발사 간격·피격 누적·행동 제한·생포 전환 | 멀리서도 실패 위험. 경고를 보고 숨을 수 있는 차폐와 회복 여부 필요 |
| 실탄 사격 | 발사 조건·명중·피해/체력·사망·아군 사격 판정 | 살상 전투·피격 생존 설계가 추가되며 현재 실패 조건과 레벨 전체 재검토 필요 |

기본 사격 없음은 잠입·추격과 교환을 먼저 완성하기 위한 추천이다. 사격안을 선택하면 플레이어의 교환용 사격과 경비 사격의 피격 효과를 구분해 설명해야 한다. 선택 전에는 경비 사격·플레이어 피격 사망이 있는 것으로 문서나 씬을 제작하지 않는다.

## 2. 우선 결정 2 — 직접 제압

**현재 확정:** 성립 즉시 무력화하며 교환을 예약하지 않는다. 제압 후 총 획득은 선택이다. 성립 방향·거리와 이후 회복/발견 반응은 아직 미정이다.

| 항목 | 💡 추천 시험안 | 확인할 실패 사례 |
| --- | --- | --- |
| 방향·인지 | 경비 뒤쪽 120° 범위(정후방 기준 좌우 60°), 해당 경비가 플레이어를 직접 보고 있지 않을 때 | 정면으로 달려가 즉시 제압하는 단일 해법 방지. 시설 경보 중이어도 개별 경비의 현재 관측과 구분 |
| 거리·장애물 | 몸체 표면 사이 유효 거리 1.2m 이내, 손이 닿는 경로에 벽·닫힌 문·유리 없음 | 벽 너머·배식구 너머 제압, 멀리 떨어진 대상에 프롬프트가 뜨는 경우 |
| 높이·자세 | 같은 보행면에서 접근하고 플레이어가 서거나 앉은 상태를 각각 검수 | 그레이팅 위·아래나 계단 아래에서 몸이 닿지 않는데 성립하는 경우 |
| 처리 | 조건이 맞으면 즉시 무력화. 교환 지연을 붙이지 않음 | 애니메이션 길이를 별도 3초 효력 지연으로 해석하지 않음 |
| 회복 | 현 층을 떠날 때까지 쓰러진 상태 유지하는 안 | 무한 대기 후 깨어나는 시간 규칙을 우선 도입하지 않음. 자동 소멸 아님 |
| 동료 발견 | 발견 지점 확인·신고·주변 수색. 직접 목격하지 않았다면 플레이어 현재 위치는 모름 | 쓰러진 몸을 봤다고 플레이어 좌표를 전역 공유하지 않음 |

제압 장면 중 플레이어 이동/회전·다른 경비의 개입·취소, 몸 배치·회수 애니메이션, 총 획득 범위는 후속 세부안이다. 옛 B5 예시의 '뒤에서 제압'과 '동료에게 달려옴'은 위 조건을 확정한 기록이 아니다.

## 3. 우선 결정 3 — 도구가 필요한 상황

현재 B5~B2 정적 씬의 보행 연결은 검수됐지만 감시·추격·도구 사용이 연결된 본편 검증은 아니다. 따라서 준비 부족 실패가 현재 발생한다고 기록하지 않는다. 도구가 있으면 편한 구간과, 특정 상태에서 도구 없이는 해결 불가능한 구간을 구분해 실제 경로 검증을 해야 한다.

| 후보 | 도구가 필요해지는 상황의 제안 | 반드시 대조할 빈손 대안 |
| --- | --- | --- |
| B4 C01–C04 접근과 C03 우회 합류부 | 경보 상태에서 전방 감시를 교환으로 넘는 상황. 짧은 투척 또는 총을 선택 가능하게 설계 | C03 우회, 숨었다 기다리기, 뒤로 접근한 제압, 다른 코어로 이동하기가 여전히 가능한지 |
| B2 C02–T01 하부와 상부 연결 | 배관 아래 감시와 상부 노출이 겹친 상태에서 교환 도구로 감시 위치를 바꾸는 상황 | 메자닌·내부 계단 우회, 경계 해제 대기, 제압. 낮은 상부에서 서 있는 경비와 교환하면 공간 부족으로 취소될 수 있음 |
| B3 소등 보관부 | 손전등으로 길·표식을 읽기 쉬워지는 보조 도구 구간 | 어둡다는 이유만으로 필수 도구/게임 오버로 판정하지 않음. 기본 출입 표식과 환경광만으로 가능한 경로도 확인 |

이들은 **미배치 후보**이며 위 두 경비 구간도 도구 필수로 확정하지 않았다. 각 후보에 진입 조건·경보·남은 경로·사용 가능 대상·필요 도구와 대체 종류·현지 획득 가능 여부·실패/재시작 경계를 적어야 한다. 좌표와 경비 배치는 감지·제압 규칙 확정 후 정한다.

검증은 ① 물건을 가진 상태, ② 빈손, ③ 탄약 0이지만 총 자체를 던질 수 있는 상태로 나눈다. 우회·대기·무장하지 않은 제압 중 하나라도 해법으로 남으면 '준비 부족으로 진행 불가'라고 부르지 않는다. 반대로 모두 막혔을 때도 단순 소지 0 검사로 실패시키지 말고, 플레이어가 위험과 필요한 행동을 읽을 수 있는지 및 어떤 사건/조건에서 게임 오버가 되는지 먼저 정한다.

코어 이용 자체에 특정 물건이나 수집 조건을 붙이지 않으며 모든 코어 선택은 유지한다. 선택한 경로·경보 상황 때문에 도구가 필요할 수 있다는 방향이다. 같은 코어로 연속 상행했을 때 이 후보들을 전부 건너뛸 수도 있으므로, **준비 부족 실패를 어느 진행 상태에서 실제로 발생시키려는지**는 아직 해결해야 할 설계 과제다. 이를 해결하지 않고 모든 경로에서 준비 실패가 성립한다고 주장하지 않는다. 새 시도에서 준비를 바꿀 수 있어야 하며 실제 하행이나 자동 지급으로 대신하지 않는다.

## 4. 경비 수치와 공간 시험

아래는 💡 첫 시험값이며 확정값·현재 Unity 동작값이 아니다. 플레이어 현재 값은 걷기 5m/s·달리기 7.5m/s·앉기 걷기 2.5m/s·앉기 달리기 4m/s다.

| 경비 항목 | 💡 시험 시작값 | 조정 기준 |
| --- | --- | --- |
| 순찰 속도 | 1.5m/s | 관측·판단할 시간과 순찰 대기 길이 |
| 추격 속도 | 6.0m/s | 플레이어 걷기보다 빠르고 달리기보다 느림. 앉은 통로는 차폐·동선으로 벗어나야 함 |
| 시야 거리 | 15m | 공동/복도 크기에 맞춰 10~20m 비교. 실제 차폐·빛 감지는 별도 |
| 수평 시야각 | 총 90° | 코너 엿보기·후방 접근과 비교. 수직 감지는 그레이팅 상하 시선 검증으로 별도 조정 |
| 붙잡기 거리 | 몸체 표면 간 0.9m 이내 | 벽·유리·그레이팅을 통과한 붙잡기 금지. 유효 접촉 경로와 높이 검사 |
| 반응 지연 | 0.35초 | 즉시 회피 불가능한 피격/발각인지, 교환의 3초가 읽히는지 |

이전 가안의 3.0m/s 추격·시야 5m는 현행 기본값으로 채택하지 않는다. 동일 높이의 직선에서 플레이어가 가만히 기다린다는 단순 가정이면, 6.0 × (3 − 0.35) + 0.9 = **16.8m**의 여유가 필요하다. 이는 시작 몸체 사이 간격 기준의 참고값이며 실제 도착 안전을 보장하는 식이 아니다. T01/T02 약 13.5~13.8m에서 '끝에서 쏘면 안전'을 그대로 적용할 수 없고, 물러남·모퉁이·이동 경로·공간 검사를 함께 시험한다. 다른 층 코어·그레이팅의 고저차도 별도로 검증한다.

## 5. 컷씬 이후 첫 수동 학습

💡 C01 포드 밖의 감시 사각에 짧은 선택형 연습 구간을 둔다. 컷씬은 능력을 보여 주고, 이 구간은 실제 입력을 경험하게 한다. 연습 성공을 코어 개방 조건으로 강제하지 않는다.

1. 식판 등 알아보기 쉬운 물건을 직접 줍고 우하단 휠로 선택한다. 컷씬이 자동으로 물건을 지급한 것으로 처리하지 않는다.
2. 연습에 사용할 대상을 식별하고 직접 던진다. 식판 같은 독립 물체의 교환 허용은 확정됐다. 💡 회수 가능한 식판과 충분한 바닥으로 연습하고, 고정된 더미/설비와의 교환을 임의 허용하지 않는다. 후속 연습에서는 한 투척의 두 대상 명중도 비교한다.
3. 실제 명중부터 3초 동안 옆으로 움직여, 내가 선 자리에 상대가 놓이는 것을 직접 경험한다. 놓친 물건은 가까이서 다시 회수할 수 있게 시험 배치한다.
4. 이동·선택·투척 안내를 확인한 뒤 위험 구간으로 나갈지 스스로 고른다. 연습을 건너뛸 수 있되 입력 안내를 다시 볼 수 있게 한다.

식판을 쓰는 연습 후보도 실제 충돌·착지·양쪽 도착 공간을 검수해야 한다. 일반 경비를 아무 설명 없이 무적·무반응으로 바꾸지 않는다. 연습 사각과 컷씬 경비의 무전이 충돌하는지도 확인한다. 안전한 조작 기회 제공은 이후 상층의 자동 보충·빈손 완주 보장과 구분한다.

## 6. 기록을 읽지 않는 경로와 이야기

동일 코어로 곧바로 오르는 플레이를 허용하므로 모든 층의 기록을 읽는 것을 전제로 엔딩을 쓰지 않는다. 💡 도입 컷씬·코어에서 지나며 들을 수 있는 짧은 방송·마지막 장면에는 탈출 목적과 엔딩을 이해하는 최소 사실을 담고, 문서·USB·샤드는 연구 목적·인물 관계·탈출 관찰의 증거와 해석을 더하는 구조를 추천한다. 어떤 사실을 필수로 전달할지는 엔딩 초안과 함께 확정한다.

같은 코어만 이용하고 기록 0개인 플레이와 선택 탐색으로 기록을 읽은 플레이를 비교한다. 앞의 경우에도 인물과 결말의 기본 인과를 이해할 수 있어야 하며, 뒤의 경우에는 탐색으로 얻은 의미가 더 있어야 한다. 반복 방송·새 층마다 강제 문서 화면을 여는 방식은 피하고, 기록을 코어 이용 조건으로 만들지 않는다. 이야기 전달을 위해 미정인 결말의 반전을 먼저 확정하지 않는다.

## 7. 이후 확정한 상호작용과 신고

| 항목 | 사용자 결정 | 남은 상세 사항 |
| --- | --- | --- |
| 기록 | 읽은 내용을 갤러리에 등록해 다시 열람 | 분류·키, 체크포인트/새 회차의 해금 보존 범위 |
| 열람 시간 | 기록·단말·갤러리 열람 중 게임 시간 정지. 비행·AI·교환·30초 신고·경보·소음 수명 포함 | UI/재생 시간과 게임 시간의 분리 검증 |
| 연속 명중 | 볼펜→경비→식판처럼 각 유효 명중 +3초에 독립 교환. 명중 간격이 교환 간격 | 같은 대상 재충돌의 판정 단위, 동일 충돌 이벤트 중복 제거 |
| 교환 속도 | 각자의 이동·낙하 속도 유지 | 시선/회전·각속도는 별도 미정 |
| 소음·어그로 | 루시드 다이버 자료를 참고하고 소음 오브젝트 풀링을 활용하는 방향 | [원본과 적용 차이](소음_어그로_루시드다이버_참조.md), 반경·강도·빛·행동 우선순위 세부 |
| 연구원 | 도주 후 게임 시간 30초 뒤 전체 경보. 가장 최근 유효 관측 위치에 경보 | 30초 시작 사건 확인 중, 신고 전 제압/중복 신고/다중 연구원 |
| 경비 | 추격하면서 무전으로 플레이어 관측 정보 전달 | 지연·갱신 간격·범위 |
| 소지 한도 | 5개면 “공간이 없어”를 표시하고 획득 거절 | UI 표시 위치/길이, 단말 삽입 물건의 소지 칸 처리 |

전체 경보가 울린다는 것과 플레이어의 현재 위치를 전지적으로 아는 것은 다르다. 관측 시각과 층이 있는 최신 유효 위치를 공유하고, 오래된 무전이 최신 위치를 덮어쓰지 않아야 한다. 30초 신고 대기 중 상행하는 경우도 경보 전달 상태에서 누락하지 않는다. 열람 중 멈춘 타이머를 닫을 때 실제 경과 시간으로 소진하지 않는다.

## 8. 추가 우선 결정과 AI 연결

붙잡기는 실패 조건이므로 사격·직접 제압과 함께 먼저 정한다. 💡 의식 있는 경비의 직접 식별, 몸체 간 기존 시험 거리 0.9m, 같은 접촉 가능 높이·차폐 없는 경로를 확인한 뒤 0.4 게임초의 붙잡기 예고를 주고 마지막에 재검사하는 안이다. 거리/시야/접촉 단절·무력화·교환 성공 시 취소하며 원거리 끌어당기기는 하지 않는다. 💡 교환 성공 뒤 새 위치에서 조건이 맞으면 예고를 처음부터 새로 시작하고, 실패한 교환은 예고를 취소하지 않는 안이다. 0.4초는 기존 반응 지연 0.35초와 별도인 미검증 값이다. [AI 6.4 붙잡기](에너미_AI_기획과_로직.md#64-붙잡기의-성립과-실패)

경비 추격 6.0m/s는 플레이어 전진 달리기 7.5m/s보다 느리므로 직선 도주는 허용되는 시험 조건이다. 멈춤·걷기·앉기·코너·관측에 근거한 경로 확인으로 잡힐 상황을 검증한다. 1명 시험에서 잡히지 않는 문제를 숨은 가속이나 협력 AI 전체 선행 구현으로 해결하지 않는다.

**사용자 결정 (2026-11-10): 붙잡기 예고 동안에도 경비는 이동·회전을 계속해 따라붙는다.** 경비가 예고 동안 제자리에 선다면 거리 0.9m·예고 0.4초로는 앞을 막아도 달리는 플레이어를 놓치기 때문이다. 옆을 스쳐 달리는 플레이어가 범위 안에 머무는 시간이 최대 약 0.36초였다. 직선에서 뒤로 도주하는 것은 계속 허용하고, 플레이어를 끌어당기지 않는다. 🟡 경비의 회전 속도와 교환 동시 처리는 남은 결정이다. 검토한 다른 세 안(예고 단축·닿으면 느려짐·경비 사격)은 [AI 6.4](에너미_AI_기획과_로직.md#64-붙잡기의-성립과-실패)에 기록으로 남긴다.

경비의 3초 뒤 위치 표시 여부도 구현 범위를 좌우하므로 우선 결정한다. 💡 첫 구현은 현재 양쪽 교환 공간·예약 시간·취소 이유 피드백까지만 만들고 미래 경비 위치 표시는 보류한다. 채택한다면 실제/예측 질의 결과를 순수 판단에 넘기며 현재 Unity Raycast 결과를 미래 결과로 쓰지 않는다. [AI 10.3](에너미_AI_기획과_로직.md#103-미리보기-범위와-월드-질의-경계)

💡 연구원은 도주 시작부터 30초를 세고 전송 전 비살상 제압으로 해당 신고만 취소하는 안을 제안한다. 제압 허용·시작 사건·동시 시각 처리는 미정이다. 채택하지 않으면 30초는 중단 기회가 아닌 경보 전 준비 시간이다. 상행은 시작한 신고를 취소하지 않는다. 관제실 무인화는 별도 제안인 CCTV 신규 호출 중단에만 쓰고 연구원 신고·이미 전달된 무전까지 지우지 않는다. [AI 8장](에너미_AI_기획과_로직.md#8-연구원과-cctv)

첫 구현의 최소 필드·실제 A.Define~F.Presenter 배치·고정 판단 간격과 단계별 범위는 [AI 3장](에너미_AI_기획과_로직.md#3-단계별-구조와-실제-코드-계층)을 따른다. 인원 범위·경보 효과·병목·이상 징후·관제실 방문 보상은 모두 시험안이며 기능 구현 결과가 아니다.
