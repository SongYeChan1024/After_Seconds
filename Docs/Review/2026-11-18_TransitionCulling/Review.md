# B5 위치 교환과 B4 층 전환 성능 점검 V0.02

작성일 2026-11-18 · 작성자 송예찬

## 적용 결과

B5 A계단에 도달한 뒤 B4에서 조작을 돌려받기까지 걸린 시간이 Windows 개발 빌드에서 824~840ms에서 30~38ms로 줄었다. 비교는 RTX 3070, Direct3D 12, 1920×1080의 실제 렌더 화면에서 같은 경로를 각 두 번 실행한 결과다.

| 측정 항목 | 수정 전 | 수정 후 |
| --- | ---: | ---: |
| B5 경비 교환 직전 52프레임 중앙값 | 15.02~15.19ms | 4.95ms |
| 경비 교환 전후 6프레임 중 최장 | 16.34 / 103.32ms | 9.36 / 10.09ms |
| 투척부터 계단 진입 전까지 프레임 시간 95백분위 | 15.68~15.81ms | 6.31~6.35ms |
| 계단 접근 후 2초 동안의 최장 프레임 | 12.13~14.28ms | 20.24~20.49ms |
| 계단참 진입부터 조작 복귀까지 | 824 / 840ms | 30 / 38ms |
| 계단참 진입·복귀 구간의 최장 단일 프레임 | 24.79~28.05ms | 20.04~27.87ms |

| 프로세스 최대 작업 집합, 200ms 간격 표본 | 3,070~3,074MiB | 2,752~2,771MiB |

계단 아래 접근에 로딩 비용 일부가 생겼고, 계단참에서 기다리는 시간이 크게 줄었다. 새 빌드 두 번 모두 계단참 도착 전 B4가 로드됐고 활성 루트는 0개였다. 두 번 모두 B4에서 입력과 시간 배율 1이 복구됐고 B5 언로드도 끝났다. 프레임 표본에는 식판에 물리 충돌을 일으킨 뒤 경비와 실제 교환하고, 계단 접근점과 계단참에 순서대로 접지한 경로를 사용했다. 화면 캡처를 요청한 직후 계단 접근점으로 시험 위치를 옮기는 프레임은 접근 구간 최장값에서 제외했다. 선로딩을 요청한 다음 프레임부터 비용을 집계했다.

화면 캡처를 끈 별도 빌드 시험에서는 투척 후 계단참 진입 직전까지 1,206프레임의 95백분위가 6.26ms, 최장이 18.64ms였다. 선로딩 완료 뒤 계단참에서 조작 복귀까지는 31ms였다. 계단 아래를 건너뛰는 두 경로도 확인했다. 선로딩을 시작한 바로 다음 프레임에 계단참에 진입하면 822ms, 접근 구간을 거치지 않고 바로 도착하면 777ms 후 조작이 복귀했다. 두 경로 모두 B4 로드 이벤트는 한 번이었고, 입력·시간 배율·B5 언로드가 정상으로 돌아왔다.

진단 스크립트를 제외한 Windows 개발 빌드도 성공했다. 타임라인 수집을 켠 별도 실행은 Profiler 버퍼가 포화돼 정량 비교에서 제외했다. 위 Windows 수치는 실제 게임 화면을 그리면서 단조 시계로 기록한 프레임 시간이다.

### 층 로딩

- Windows 빌드는 B5 A계단의 수평 반경 8m, 위아래 높이 차이 19m 안에 들어오면 B4 한 층을 비동기로 미리 읽는다. 플레이어가 다른 방에 있을 때는 B5부터 조작할 수 있다.
- 에디터에서는 텍스트 씬 역직렬화가 길어 B5 시작 로딩 화면에서 B4를 준비한다. 이 때문에 에디터 최초 플레이 대기 시간이 늘어날 수 있다. 선로딩한 씬은 원래 켜져 있던 루트만 기억해 첫 물리 스텝 전에 비활성화한다. 도착을 확정할 때 원래 상태로 복구한다. [씬 전환 코드](../../../Unity/After_Seconds_Build_V0.01/Assets/Afrer_Seconds/02.Scripts/E.Manager/SceneFlow.cs)
- 에디터에서 경비에게 붙잡힌 뒤 재시작해도 같은 대기 씬을 재사용했다. 도착 위치에 장애물을 놓았을 때 B5 입력과 식판을 유지했고 B4는 다시 비활성화됐다. 장애물을 치운 뒤 다시 진입하면 같은 플레이어·카메라·식판으로 B4에 도착했다. 성공 재진입은 총 153ms, 최장 프레임은 126ms였다. 수정 전 에디터의 최장 단일 프레임은 3.05~4.40초였다.

### B5 조명과 LOD

- 활성 광원 328개의 조명은 유지했다. 실시간 그림자를 쓰는 활성 광원은 115개에서 16개로 줄였다. 배식구 내부등, 경비 쪽 벽 작업등, 방별 천장 주광원과 계단참 조명이 그림자를 맡는다. 고정 시점 에디터에서 드로우 콜은 8,555회에서 2,263회, GPU 프레임 중앙값은 약 19.6ms에서 7.6~7.8ms로 줄었다. 수정 후 오클루전을 끄면 드로우 콜이 다시 3,921회로 늘어 차폐도 계속 작동함을 확인했다.
- 아래 사진은 같은 시작 위치에서 식판을 든 화면이다. 왼쪽이 수정 전이고 오른쪽이 수정 후다. [B5 조명 비교](B5_ShadowComparison.jpg)
- T11은 6개, T19는 8개 구간으로 나눠 각각 3단계 LOD를 적용했다. 바닥·케이블처럼 구간 경계를 가로지르는 면은 연속된 메시 하나로 그린다. 원본과 근거리 모델의 삼각형 593,896개는 정점 위치를 0.1mm, UV를 소수점 셋째 자리로 반올림한 비교에서 재질을 포함해 모두 일치했다. 기존 충돌체를 사용하는 구조다. [Blender 생성 스크립트](../../../SourceAssets/B5_CorridorLOD/build_sections.py)

## 수정 전 에디터 진단

A계단에서 B4에 진입하는 순간에 가장 긴 멈춤이 반복됐다. 식판으로 경비와 자리를 바꾸는 동작은 두 번 모두 40ms 안팎이었다. B5에서는 가만히 서 있을 때도 주변 조명의 실시간 그림자를 그리는 비용이 컸다.

## 실제 플레이 경로

Unity 6000.4.0f1 에디터, Windows, RTX 3070, Game 뷰 1920×1080, PC URP에서 측정했다. `GameRoot`로 시작해 B5를 추가 로드했다. 프레임 시간은 연속된 두 플레이 프레임 사이의 실제 경과 시간이다. 배포용 플레이어의 프레임 시간은 별도 측정이 필요하다.

| 관측값 | 1회 | 2회 |
| --- | ---: | ---: |
| 경비와 교환하기 직전 27프레임 중앙값 | 37.6ms | 36.4ms |
| 경비의 위치 교환 이벤트가 발생한 프레임 | 41.9ms | 39.5ms |
| 계단 진입 직전 31프레임 중앙값 | 30.6ms | 30.2ms |
| B5 → B4 전환의 최장 단일 프레임 | 4,397ms | 3,048ms |
| B4 로드 작업 전체, Unity Editor.log | 5.44초 | 3.86초 |
| 그중 씬 데이터 역직렬화 / 씬 통합 | 4.37초 / 331ms | 3.03초 / 316ms |
| B4 도착 후 약 2초간 프레임 중앙값 | 12.3ms | 12.0ms |

식판을 줍고 던진 뒤 마지막 접근 구간에서 식판에 재현용 속도를 줬다. 실제 충돌과 3초 뒤 경비의 위치 교환 이벤트를 기준으로 측정했다. 층 전환은 첫 회에 계단으로 걸어 들어갔다. 두 번째 보행 시험은 착지점에 도달하지 않아 층 전환 집계에서 제외했다. 두 번째 층 전환 수치는 같은 착지점에 플레이어를 접지시켜 정상 전환 경로를 다시 실행한 결과다. 두 전환 구간 모두 관리 힙의 0세대 GC 횟수 증가는 0회였다.

`SceneFlow.Travel`은 착지 뒤 로딩 화면을 켜고 게임 시간과 입력을 멈춘다. 이어 B4를 추가 로드하고, 도착 공간을 확인한 뒤 B4를 활성 씬으로 지정하고 B5 언로드가 끝나면 조작을 돌려준다. 첫 번째 긴 프레임이 로딩 화면을 관측한 시점에 이미 끝나 있었다. 로딩 화면이 켜져 있는 시간만 재면 체감 멈춤을 과소평가한다. [전환 코드](../../../Unity/After_Seconds_Build_V0.01/Assets/Afrer_Seconds/02.Scripts/E.Manager/SceneFlow.cs)

## 카메라 컬링과 LOD

메인 카메라의 오클루전 컬링은 켜져 있다. 원거리 클리핑은 1,000m이고 32개 레이어의 개별 컬링 거리는 모두 기본값 0이다. B5와 B4는 층별로 베이크한 오클루전 데이터를 사용한다. 두 층 모두 최소 차폐물 크기 5m, 최소 구멍 크기 0.25m다. PC 품질의 LOD Bias는 2이며 가장 정밀한 LOD 0부터 표시한다.

각 시점에서 카메라와 게임 시간을 고정하고 조건마다 10프레임을 기다린 뒤 45프레임의 중앙값을 구했다. 설정을 되돌려 같은 결과가 나오는지도 확인했다. 드로우 콜과 삼각형은 Unity 렌더 통계에 잡힌 패스 합계로, 그림자에 같은 메시가 반복 제출된 횟수도 포함한다.

| 고정 시점과 설정 | 드로우 콜 | 렌더 삼각형 | 프레임 중앙값 |
| --- | ---: | ---: | ---: |
| B5 시작 위치, 오클루전 켬 · Bias 2 | 8,555 | 4,470만 | 36.8~37.6ms |
| 같은 위치, 오클루전 끔 · Bias 2 | 10,957 | 5,533만 | 39.3~40.4ms |
| 같은 위치, 오클루전 켬 · Bias 1 | 8,555 | 4,470만 | 36.3ms |
| B4 도착 계단, 오클루전 켬 · Bias 2 | 2,140 | 741만 | 12.2~12.4ms |
| 같은 위치, 오클루전 끔 · Bias 2 | 5,681 | 1,567만 | 14.1~14.5ms |
| 같은 위치, 오클루전 켬 · Bias 1 | 2,133 | 687만 | 12.1~12.2ms |

- **B5**에서 활성 MeshRenderer 1,144개 중 1,133개가 LOD 그룹 밖에 있었다. 등록된 그룹 4개는 모두 LOD 1에서 삼각형 수가 줄었다. 그룹 밖의 메시를 배치 수만큼 합하면 약 1,166만 삼각형이다. 복도 마감 메시 중 `RD_T19_Finish` 한 개가 344,676개, `RD_T11_Finish`가 249,220개다.
- **B4**는 3단계 LOD 그룹 733개가 모두 유효했다. LOD 0에서 1로 내려갈 때 등록된 메시의 삼각형 합계가 701만에서 301만으로 줄었다. 현재 계단 시점에서도 Bias를 조절하면 실제 렌더 삼각형 수가 달라졌다.

## 실시간 그림자 비용

조명을 켜 둔 채 해당 층 점광원과 스폿광원의 그림자만 일시적으로 껐다. 순서는 켬 → 끔 → 끔 → 켬이며 카메라, 오클루전, LOD Bias는 고정했다. 기본 설정의 그림자 거리는 50m, 추가 광원 그림자 아틀라스는 4096이다. [PC 렌더 설정](../../../Unity/After_Seconds_Build_V0.01/Assets/Settings/PC_RPAsset.asset)

| 항목 | B5 시작 위치 | B4 도착 계단 |
| --- | ---: | ---: |
| 층에 활성화된 그림자 광원 | 점광원 22 + 스폿광원 93 | 스폿광원 233 |
| 그림자 켬 → 끔, 드로우 콜 | 8,552 → 865 | 2,159 → 83 |
| 그림자 켬 → 끔, 프레임 중앙값 | 36.0~36.2 → 11.4ms | 11.8~12.9 → 8.4~9.4ms |
| 그림자 켬 → 끔, GPU 프레임 중앙값 | 19.4~19.7 → 6.5~6.6ms | 4.4~5.3 → 3.4~3.8ms |

광원 개수는 층 전체 집계다. 이 비교는 그림자 비용의 규모를 확인하는 실험이며, 일부 조명만 조정했을 때 얻을 프레임은 다시 측정해야 한다.

## 수정 전 제안한 작업 순서와 확인 기준

1. **계단 진입 전에 B4 로드 비용을 분산한다.** 먼저 Windows Development Build에서 첫 진입과 재진입의 메인 스레드 타임라인을 캡처한다. 계단 아래에서 B4 선로딩을 시작하고, 무거운 작업을 요청하기 전에 전환 화면이 한 프레임 실제로 표시되도록 한다. 선로딩을 시작한 지점에서도 끊기거나 활성화 비용이 크면, 계단·도착 방을 먼저 준비하고 나머지 방 장식과 조명을 구역 단위로 나눠 불러온다. 두 층이 겹치는 동안 반대 층의 충돌·렌더·경비가 먼저 활성화되지 않게 하고 메모리 최고점도 잰다.
2. **B5 배식구와 경비가 서는 복도부터 그림자를 줄인다.** 플레이어가 경비의 움직임을 그림자로 읽는 주광원을 먼저 지정한다. 고정 설비와 벽면의 보조등은 베이크하거나 실시간 그림자를 끈다. 구역별로 적용하면서 경비 실루엣, 계단 표지, 배식구 깊이감과 같은 시점의 드로우 콜·프레임 시간을 함께 비교한다.
3. **B5 복도 마감에 LOD를 추가한다.** 삼각형 수가 큰 T19·T11부터 모서리와 실루엣을 보존한 중·원거리 메시를 만든다. 코너 너머까지 한 메시로 묶여 있으면 시야가 끊기는 위치에서 나눠 컬링 단위를 맞춘다. 시작 위치, 경비 교환 직후, 계단 접근 지점에서 단계 전환과 디테일 튐을 확인한다. B4는 같은 비용으로 얻는 이득이 작은 전역 Bias 조정보다 무거운 잔여 메시를 개별 검토한다.
4. **같은 동선으로 통과 기준을 확인한다.** 제안 기준은 대상 PC의 1080p 빌드에서 조작 구간 95백분위 16.7ms 이내, 위치 교환 전후 50ms 초과 프레임 0회다. 조작 중인 상태에서 선로딩과 계단 진입을 각각 통과시키고, 첫 실행과 반복 실행을 구분한다. 로딩 화면 표시까지의 지연, 가장 긴 단일 프레임, 조작 복귀까지 걸린 시간은 따로 기록한다.
